# ToDo List — просунутий рівень (frontend + backend)

Список справ у стилі "паперового чека". Завдання зберігаються **на сервері**,
у файлі `server/data/tasks.json` — не в localStorage браузера.

## Структура проєкту

```
todo-advanced/
├── package.json
├── server/
│   ├── index.js          ← Express-сервер + API
│   └── data/
│       └── tasks.json    ← "база даних" у вигляді файлу
└── public/
    └── index.html         ← весь frontend (HTML+CSS+JS в одному файлі)
```

## Як запустити

1. Встановити залежності (потрібен Node.js, версія 18+):
   ```bash
   npm install
   ```
2. Запустити сервер:
   ```bash
   npm start
   ```
3. Відкрити у браузері:
   ```
   http://localhost:3000
   ```

Сервер віддає `public/index.html` як статичний файл і одночасно
обробляє запити до `/api/tasks`.

## API

| Метод  | Шлях              | Опис                                   |
|--------|-------------------|-----------------------------------------|
| GET    | `/api/tasks`      | Отримати всі завдання                  |
| POST   | `/api/tasks`      | Додати завдання `{ "text": "..." }`    |
| PATCH  | `/api/tasks/:id`  | Оновити завдання `{ "done": true }`    |
| DELETE | `/api/tasks/:id`  | Видалити одне завдання                 |
| DELETE | `/api/tasks`      | Видалити всі завдання                  |

Кожне завдання має вигляд:
```json
{ "id": "mqtm4jg6u7nv3", "text": "Купити молоко", "done": false, "createdAt": "2026-06-25T14:43:53.334Z" }
```

## Чому файлова система, а не localStorage

Завдання вимагає, щоб дані зберігались не у браузері, а на сервері.
Тут це зроблено найпростішим надійним способом — JSON-файл, який
сервер читає й перезаписує при кожній зміні (`fs/promises`). Це легко
змінити на справжню базу даних (наприклад, SQLite чи MongoDB) — досить
замінити функції `readTasks()` / `writeTasks()` у `server/index.js`,
інтерфейс API залишиться той самий.

## Стійкість до збоїв мережі

Якщо сервер недоступний, інтерфейс показує статус "сервер недоступний",
блокує форму додавання та виводить повідомлення про помилку — замість
того, щоб мовчки втрачати дані користувача.
